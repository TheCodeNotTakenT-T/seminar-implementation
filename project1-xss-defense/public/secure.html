🛡 Secure — Trusted Types

✅ DOM XSS — Secure Page

This page enforces the browser's Trusted Types API via a Content-Security-Policy header set by the server. Even if an attacker injects a malicious payload through the URL, the browser refuses to pass raw strings to dangerous sinks like document.write() or innerHTML.

How the Defense Works

1
The server sends Content-Security-Policy: require-trusted-types-for 'script'; trusted-types dompurify-policy. This tells the browser to block any raw string written to an injection sink.
2
A single, named Trusted Types policy (dompurify-policy) is registered. Its createHTML() callback runs DOMPurify.sanitize() on every input before returning a TrustedHTML object.
3
When the page attempts element.innerHTML = policy.createHTML(userInput), the browser verifies the value is a TrustedHTML instance and permits the write. Malicious tags like <script>, <img onerror>, etc. are stripped by DOMPurify inside the policy.

Sanitized Output

The URL parameters are processed through the Trusted Types policy. Any dangerous markup is stripped before reaching the DOM.

Trusted Types Policy — Source

// Register the ONLY allowed policy
const policy = trustedTypes.createPolicy("dompurify-policy", {
  createHTML: (unsafeString) => {
    // DOMPurify strips all dangerous tags/attributes
    return DOMPurify.sanitize(unsafeString, {
      ALLOWED_TAGS: ["b", "i", "em", "strong", "span", "p", "br"],
      ALLOWED_ATTR: ["class", "id"],
    });
  },
});

// Usage — the browser enforces that innerHTML receives TrustedHTML
element.innerHTML = policy.createHTML(userInput);

Try the same bypass URL: /secure?id=<scr&name=ipt>alert('XSS')</script> — the script tag will be completely stripped.
